# A2 fused layer: fuse activation into conv/tail — measured (rejected)

Date:       2026-07-14  
Machine:    Apple M2 (arm64)  
Workload:   `ORNG-V30-e609-Center.nam --slim 1.0` and `A2.nam --slim 1.0`  
            48 kHz, buffer 64, Release, fused ON  
Tool:       `tools/benchmodel`

## Variants tried

All kept numerical parity (`run_tests` fused suite green while active).

1. **Act in-register at end of `conv_tile` (before store)**  
   - `process` self-time dropped; `conv_block` grew.  
   - Wall: ~40–41 ms (no win; long run slightly worse).

2. **Act in-register at start of `tail_tile` (on load)**  
   - Similar: process overhead down, tail up.  
   - Wall: ~40.3 ms ORNG (noise vs baseline). Long run 6473 vs 6560 ms (~1%).

3. **Full `layer_neon` = conv + act + tail, no `_z` spill**  
   - T=2 tiles: **~61 ms** ORNG (~1.5× regression); A1 also ~55 ms.  
   - T=4 tiles: still clearly slower than three-pass on A1 probe.  
   - Dominant cost moved into `layer_neon_block` — dilated GEMM lost efficiency to register pressure from holding act + 1×1 in the same tile.

## Conclusion

For A2 (8-ch LeakyReLU) on M2, the separate activation pass is **not** a meaningful CPU lever. The dilated `conv_block` already owns ~75% of time; forcing act/tail into that kernel hurts more than the saved L1 pass helps.

**Shipped code:** restored three-pass fused engine (baseline performance). Comment left on `apply_activation` documenting the measurement.
