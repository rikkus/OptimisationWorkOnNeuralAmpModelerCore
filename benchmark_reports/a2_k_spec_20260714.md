# Fused conv: compile-time K specialization (3 / 6 / 15)

Date:       2026-07-14  
Machine:    Apple M2  
Change:     `conv_block` dispatches `num_taps ∈ {3,6,15}` to `conv_block_k<Q,K>`
            so the dilated tap loop is a compile-time constant (A2 uses 6/15;
            A1 standard uses 3). Other K keep the runtime loop.

## A/B (ORNG @ slim 1.0, 10 s audio, cool runs)

| Build | Wall (3 runs) | ~median |
|---|---|---:|
| Runtime taps only | 223 / 215 / 216 ms | **~216 ms** |
| K-spec (3/6/15) | 217 / 249† / 215 ms | **~216 ms** |

† Thermal / scheduling outlier. Excluding it, specialized matches baseline.

A1 standard (K=3) similarly within noise either way (~208–227 ms / 10 s).

## Conclusion

On this M2, **no material amp win** from K=6/15 specialization — the compiler
already schedules the short runtime tap loop well when `num_taps` is small
and hot. Specialization is retained as low-risk / documentation of the common
shapes; next amp lever remains **SME (M4+)** or product slim/nano.

Parity: `run_tests` fused suite green.
